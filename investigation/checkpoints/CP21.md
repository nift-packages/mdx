# CP21 — representative installed site certification

Linux, pinned unmodified Nift4.6 core, Node22.22.1 and explicit globally pinned
runtime. Actual Git-installed package in a space/Unicode project path. All
100/500/1000 targets build ordinary HTML; every build uses one helper invocation
and one version probe. Warm builds retain target outputs while the mandatory
prepare hook refreshes the batch. Sources include frontmatter, GFM, fences,
semantic Aside and shared MDX.

The full renderer suite certifies installed facade/direct composition and
document/adapter/transitive-JS/config/plugin/declared-asset invalidation, exactly
once dependency metadata, unrelated-target stability and no-change builds.
The documentation example independently certifies copyable installation/build.
34 local tests pass45.573s; Linux/macOS Node22/24 CI passes at2c7024f.

Raw timing and memory evidence: CP21-site-results.json. Measurements are one
local run per size, not universal performance promises; final evidence is rerun
without overlapping local benchmarks. GNU time reports the maximum resident
size observed for a process in the command tree, not aggregate concurrent memory.
Both the package parser and renderer are included in full-build wall time.

A separate identical100-source workload includes Nift parsing, expression/Aside
rendering and transport: scalar49.892s/100 helpers versus batch2.937s/one helper.
HTML matches exactly; peak process RSS110,048/131,748KiB. This is parse+render,
not a substitute for the full installed-site measurements. CP21-scalar-batch.json
contains raw results. Normal file rendering retains batch orchestration; no
per-target scalar fallback was introduced.

Parser work remains the dominant large-build cost, including no-change builds.
The optional helper cache does not remove it. See CP15/16 for earlier cold/warm
and cache-enabled stage measurements; no daemon is claimed to fix parser cost.
