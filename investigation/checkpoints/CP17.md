# CP17 — persistence explicitly deferred

Do not add a daemon. Normal site orchestration already amortizes one worker
startup across100/500/1,000 pages, with one helper invocation independent of
target count. At1,000 pages unchanged build44.821s contains39.432s pre-hook
parser time and5.155s complete preparation; actual worker work4.033s. Removing
startup entirely could recover only part of the remaining~1.122s preparation
overhead, not the39s parser cost. At100 pages cache hits reduce rendering stages
to zero yet full pipeline is still3.981s.

Scalar rendering remains an explicit one-off convenience for inline documents;
there is no certified workload requiring persistent process-per-page sessions.
A daemon would introduce ownership/restart/multi-build/Windows/process-policy
complexity while leaving the measured bottleneck. Reconsider only with measured
scalar workloads after parser performance is adequate. No daemon claims or
untested lifecycle behavior are exposed. Decision uses CP15/CP16 evidence; no
new runtime behavior or redundant tests introduced.
