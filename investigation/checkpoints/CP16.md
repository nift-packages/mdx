# CP16 — optional content-addressed helper cache

Implemented opt-in `cache: "content"`, disabled by default. SHA256 key covers
complete document/registered graph, shared adapter/plugin/declared asset inputs,
options including policy, helper and lock bytes, actual runtime package trees
(including symlinks), Node version/platform/architecture and full environment.
Trusted arbitrary time/random/network/process effects cannot be fingerprinted;
caching requires deterministic authored inputs and declared filesystem I/O.
Config/modules still load before hits; no execution-policy bypass.

Atomic unique-temp writes, checksummed records, project-confined cache paths,
corrupt misses and dependency re-registration are implemented. The normal
pre-build batch remains mandatory; this caches rendering, not parser results.

Acceptance:30 renderer tests pass40.170s; final targeted cache test19.117s after
symlink/platform fingerprint tightening. Coverage: cold/warm HTML+dependency
parity, graph/adapter closure/plugin/asset/options/helper/lock/environment
mutations, corrupt JSON, missing dependency, disable, policy denial and two
simultaneous cold writers. Runtime package bytes and process version are
fingerprinted; no mutation of user's globally installed packages was needed.

Installed100-page benchmark:7.504s cold,4.223s first incremental (hook mode
changes environment),3.981s next unchanged build with100 cache hits. Compile,
evaluate and render stage sums become zero on hits; parser2.882s dominates.
Raw evidence CP16-site-results.json. This does not establish a broad performance
win: simple documents can cost less to compile than runtime/input fingerprinting.
Keep default off, and retain Capgo's unresolved parser-scale gate.
