# CP23 — Compiler-semantic preparation and native filesystem integration

Authorized by the subsequent user implementation outline for both Capgo experiments. Existing CP22 history remains evidence of the earlier gate, not a permanent rejection.

Added explicit `renderer/prepare.mjs` trusted path preparation and `mdx.prepared(path)` → `mdx.html(...)` rendering envelope. Preservation parse/input remain unchanged apart from replacing the known broken directory heuristic with Nift's proper `is_dir` API. The core change is owned by the separate Nift task; this package pins landed core `adcd3a685da3586566326f69628a2252b2b37527` in its six-platform CI and does not modify core.

Preparation reuses compiler AST import traversal, registers graph closure, rejects dynamic imports/reexports/cycles/escapes, validates lexical/canonical dependency fingerprints before cache hits, and writes stable per-root records atomically. Prepared consumers register source, artifact and complete dependencies. A mandatory hook runs for full/incremental/target builds; there is no implicit per-page Node fallback. Worker deadline, source/protocol and resource bounds remain. Generic components/config/plugins/declared assets stay explicit.

Local evidence: 165 byte-exact parser parity cases pass; original parser/DFS/no-process/incremental regression passes; trusted/bounded profile boundaries pass. Existing renderer suite passes 34 tests (one Windows-only case skipped on Linux). New Node preparation checks cold/no-change/transitive edits/unrelated target stability, adapter edits, cycle, escape, policy, dynamic/reexport refusal and symlink retarget. Six-platform certification is rerun by CI after this commit; Windows restoration requires actual green jobs, not the local Linux result. Site-level integration and all-Capgo budgets remain part of the experiment checkpoints.

Cache manifests include current source, options, runtime identity, HTML checksum, dependencies and requested→canonical content fingerprints. Trusted plugins/adapters must declare any extra non-import file inputs. Conservative shared adapter dependencies can fan out to all consumers; exact laziness is an optimization, not a correctness shortcut. No preservation object limit is raised.
