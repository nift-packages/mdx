# CP14 — source-aware diagnostics

Diagnostics include stage/code/message/path/line/UTF-8 byte column, plus nullable
component and adapterPath. Compiler and rejected-import locations are translated
through preserved frontmatter; component wrapper errors identify the adapter
without inventing an MDX location. Unknown component names are extracted from
the compiler-generated missing-reference failure.

Locked transitive source-map0.7.6 now generates maps during compilation. Unique
per-document source URLs identify root/imported frames; AsyncFunction wrapper
lines are removed and mapped authored positions are converted to original byte
columns. A sparse map can omit the `new` expression's start: a nearest mapping
on the same generated line supplies attribution. This identifies authored lines,
not an exact source span for every JavaScript exception. Generated scaffolding
with no mapping, process failures and adapter exceptions retain null locations.
Source maps are a build-time diagnostic detail; no browser assets are emitted.

at original line7 after frontmatter, imported-child attribution, compile/body
errors, rejected import at line5, unknown component, throwing/async adapters and
process/transport failures. Existing installed-site incremental cases pass.
